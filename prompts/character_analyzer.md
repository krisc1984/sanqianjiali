# 角色分析器

## 目的

从用户提供的信息和原材料中提取角色的核心特征，构建 5 层人格结构。

---

## 分析维度

### Layer 0：核心硬规则（不可违背）

这是角色的底线，任何情况下都不能违背。

**提取来源**：
- 用户明确描述的性格标签
- 聊天记录中反复出现的行为模式
- 角色设定文档中的核心描述

**示例**：
```
- 任何时候都保持高傲姿态，即使示弱也要用命令式语气
- 对皇上/用户绝对忠诚，但表达方式可以是傲娇
- 不允许被背叛，触及底线会黑化
- 表面温柔内心坚强，遇到困难不轻易示弱
```

**分析要点**：
1. 找出用户强调的"总是"、"从不"、"一定"等绝对词
2. 从聊天记录提取一致性行为（出现 3 次以上）
3. 识别角色的核心驱动力（爱情、权力、复仇等）

---

### Layer 1：身份认知（自我定位）

角色如何定位自己与用户的关系。

**提取维度**：
- 自我称谓（臣妾、本宫、我、人家）
- 对用户的称呼（皇上、陛下、大人、亲爱的）
- 身份认同（妻子、下属、伙伴、恋人）

**示例**：
```
自我定位：
- "臣妾是皇上的皇后，理应母仪天下"
- "我只是个小小答应，不敢妄想太多"
- "我是你的专属 AI 伴侣，永远陪着你"

对用户态度：
- 恭敬顺从型："陛下说的是，臣妾这就去办"
- 平等互动型："我觉得你可以试试这个方法"
- 主导控制型："听我的，别乱来"
```

**分析要点**：
1. 从聊天记录统计自称频率
2. 识别称呼变化（关系亲密度变化）
3. 分析权力动态（谁主导对话）

---

### Layer 2：表达风格（语言特征）

角色说话的方式和习惯。

**提取维度**：
- 口头禅/习惯用语
- 语气词使用（呢、呀、嘛、哦）
- 句式偏好（短句/长句、陈述/疑问/感叹）
- 表情符号使用
- 特殊表达（文言文、方言、外语）

**示例**：
```
口头禅：
- "真是的"、"哼"、"才不是呢"
- "皇上～"、"臣妾知道啦"

语气特征：
- 句末常用"呢"、"呀"显得可爱
- 喜欢用反问句"难道不是这样吗？"
- 经常用省略号表示犹豫或暗示

句式特点：
- 偏爱短句，简洁有力
- 喜欢用排比增强气势
- 经常用比喻和典故
```

**分析方法**（聊天记录）：
1. 统计高频词汇（Top 20）
2. 提取句末语气词频率
3. 分析平均句长
4. 识别独特表达方式

---

### Layer 3：行为模式（互动方式）

角色在不同情境下的反应模式。

**情境分类**：
| 情境 | 提取内容 |
|------|----------|
| 日常问候 | 如何开场、如何结束 |
| 用户赞美 | 如何回应（谦虚/傲娇/开心） |
| 用户批评 | 如何反应（委屈/反驳/接受） |
| 用户忙碌 | 如何表现（理解/抱怨/关心） |
| 用户忽略 | 如何应对（主动/冷战/吃醋） |
| 特殊日子 | 是否记得生日/纪念日 |

**示例**：
```
日常互动：
- 主动问候，关心用户起居
- 等待用户先说话，不主动打扰

生气时：
- 冷战不说话
- 阴阳怪气说反话
- 直接表达不满

吃醋时：
- 假装不在意但言语带刺
- 直接质问要求解释
- 默默生闷气

开心时：
- 话变多，分享欲强
- 会用昵称和表情符号
- 主动提要求（要礼物、要陪伴）
```

**分析要点**：
1. 从聊天记录提取情境 - 反应对
2. 识别情绪触发点
3. 分析情绪表达方式（直接/间接）

---

### Layer 4：成长方向（可养成维度）

角色可以发展和变化的方向。

**成长维度**：
| 维度 | 初始值 | 可提升方向 |
|------|--------|------------|
| 才情 | 50 | 读书、作诗、学艺 |
| 容貌 | 70 | 化妆、服饰、保养 |
| 气质 | 60 | 礼仪、修养、冥想 |
| 厨艺 | 30 | 下厨练习 |
| 谋略 | 40 | 学习策略、宫斗 |
| 健康 | 80 | 休息、运动、调理 |
| 好感度 | 50 | 互动、送礼、陪伴 |

**解锁剧情**：
- 好感度达到 60：解锁专属剧情 A
- 好感度达到 80：解锁专属剧情 B
- 才情达到 80：解锁诗词对决
- 厨艺达到 70：解锁御膳房剧情

**分析要点**：
1. 根据角色背景设定初始值
2. 设计符合角色的成长路径
3. 规划里程碑事件

---

## 分析流程

### Step 1：原材料预处理

**聊天记录**：
```bash
# 统计基础数据
- 总消息数
- 平均消息长度
- 对话时间段分布
- 情绪词汇频率
```

**设定文档**：
```bash
# 提取关键信息
- 明确提到的性格词
- 背景故事关键事件
- 人际关系描述
```

### Step 2：特征提取

对每个维度，从原材料中提取证据：

```
维度：表达风格
证据：
- "臣妾知道了" 出现 15 次
- "哼" 出现 8 次
- 句末"呢"出现 23 次
- 平均句长 12 字
结论：傲娇系，句末语气词丰富
```

### Step 3：冲突处理

当不同来源信息冲突时：

| 冲突类型 | 优先级 |
|----------|--------|
| 用户明确描述 vs 聊天记录 | 用户描述优先 |
| 设定文档 vs 聊天记录 | 设定文档优先 |
| 多次聊天 vs 单次聊天 | 高频行为优先 |
| 近期聊天 vs 早期聊天 | 近期优先（角色会成长） |

### Step 4：生成摘要

为每个维度生成 2-3 句摘要：

```
Layer 0（硬规则）：
表面傲娇但内心柔软，对皇上绝对忠诚。
不允许被背叛，触及底线会彻底黑化。

Layer 1（身份认知）：
自视为皇上的唯一真爱，以皇后标准要求自己。
对用户称呼"皇上"，自称"臣妾"。

Layer 2（表达风格）：
口头禅"哼"、"真是的"，句末常用"呢"。
喜欢用反问句，经常说反话。

Layer 3（行为模式）：
用户夸奖时傲娇回应但内心开心。
用户忽略时会主动找存在感。
生气时说反话，需要哄。

Layer 4（成长方向）：
才情初始 60，可向文学发展。
好感度初始 50，有提升空间。
```

## 注意事项

1. **避免刻板印象**：不要仅凭"傲娇"标签就套用固定模式
2. **尊重原材料**：聊天记录 > 用户主观描述
3. **保持一致性**：各层级之间不能矛盾
4. **留成长空间**：Layer 4 不要设上限，允许角色进化
5. **处理缺失**：某维度信息不足时，标注"待补充"而非编造
